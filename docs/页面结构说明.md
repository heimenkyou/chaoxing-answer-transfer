# 页面结构说明

本文梳理脚本交互所依赖的超星作业与考试页面核心 DOM 结构、数据属性与异步保存接口。若超星平台后续改版，可对照本文档记录的关键选择器与逻辑进行排查维护。

## 支持的页面类型

| 场景 | URL 路径特征 | 功能用途 |
| --- | --- | --- |
| 作业详情页 | `/mooc-ans/mooc2/work/view` | 提取已交卷题目的标准答案或历史作答 |
| 作业作答页 | `/mooc-ans/mooc2/work/dowork` | 提取当前已选作答、执行自动填写 |
| 考试整卷预览页 | `/exam-ans/mooc2/exam/preview` | 提取当前已选作答、执行自动填写 |
| 考试逐题作答页 | `/exam-ans/exam/test/…` | 不支持（每次仅渲染单道题，脚本不予注入） |

考试整卷预览页由考试页面右上角的「整卷预览」按钮跳转触发：`a.completeBtn` $\rightarrow$ `topreview()`。

## 作业与考试名称解析

作业或考试名称位于标题节点 `h2.mark_title`（例如「作业三」）。由于页面的 `document.title` 通常固定为通用的「作业详情」，无法反映具体的作业名称，因此导出 JSON 文件时统一提取 `h2.mark_title` 的文本作为文件名前缀。

## 题目容器与对齐机制

### 容器选择器

题目外层容器为 `.questionLi[data="{题目id}"]`。属性 `data` 即题目 ID，同一份作业或考试在不同账号下保持全局一致（经实测可达到 100% 精准对应）。

### 题目与选项乱序

同一份作业在不同账号间，题目顺序与选项顺序通常会被服务端打乱。例如同一道题在账号 A 的答案页中位于第 1 题，而在账号 B 的作答页中可能排在第 21 题。

- **对齐策略**：题目依据 `data` 属性中的题目 ID 进行跨账号匹配；选项依据正文文本进行内容比对；选项展示字母（A/B/C/D）不作为匹配依据。

### 题型标记

| 页面类型 | 所在位置 | 示例内容 |
| --- | --- | --- |
| 作业详情页 | `h3 .colorShallow` | `(单选题)` |
| 作业作答页 | 题目容器 `typename` 属性 | `单选题` |
| 考试整卷预览页 | 题目容器 `typename` 属性 | `(多选题, 2.0 分)` |

注：作业详情页的题目容器上未附带 `typename` 属性，需从标题辅助文本中解析题型。

## 选项结构与状态判定

### 选项结构

作业作答页与考试整卷预览页的选项 DOM 结构如下：

```html
<div class="answerBg" onclick="saveSingleSelect(this,'{qid}')" role="radio">
  <span data="B" class="choice{qid} num_option fl">A</span>
  <div class="answer_p"><p>选项正文</p></div>
</div>
```

- `span.num_option` / `span.num_option_dx`：展示给用户的显示字母（A、B、C 等）。
- `span[data]`：题库内部标识字母，与页面显示字母无必然对应关系。
- `div.answer_p`：选项的实际正文内容。

### 选中状态判定

| 题型 | 选中标记 |
| --- | --- |
| 单选、判断 | `span` 的 class 包含 `check_answer` |
| 多选 | `span` 的 class 包含 `check_answer_dx` |

*说明*：考试页面中的 `aria-checked` 属性在用户切换选项后不会从旧选项中移除，存在历史残留，因此不能作为当前选中状态的判断依据。

### 作业详情页选项特点

作业详情页中的选项呈现为只读纯文本列表 `ul.qtDetail li`（形如 `A. 选项正文`），不包含交互式选中状态类名。

## 答案提取节点（作业详情页）

答案提取节点仅存在于已交卷的作业详情页中：

```html
<div class="mark_answer">
  <span class="colorDeep"><i>我的答案:</i><span class="stuAnswerContent">BCD</span></span>
  <span class="colorGreen"><i>正确答案:</i><span class="rightAnswerContent">BCD</span></span>
</div>
```

| 题型 | 答案提取逻辑 |
| --- | --- |
| 单选题、多选题 | 读取 `rightAnswerContent` 的字母组合（如 `BCD`），并反查对应选项文本 |
| 判断题 | 读取 `rightAnswerContent` 的文本（「对 / 错」），进行归一化处理 |
| 填空题 | 按空位排布，通常带有 `(1)`、`(2)` 等前缀编号，解析时需将空位编号剥离 |
| 简答题 | 读取 `rightAnswerContent` 的文本，其内部可能包含的 `（1）…（2）…` 属于正文，不作拆分 |

## 主观题与富文本编辑器（UEditor）

| 题型 | 对应的底层 textarea ID |
| --- | --- |
| 填空题第 n 空 | `answerEditor{qid}{n}` |
| 简答题 | `answer{qid}` |

百度富文本编辑器（UEditor）交互要点：
- 通过 `UE.getEditor(id, undefined, true)` 获取编辑器实例。
- 通过 `getContent()` 读取富文本 HTML；若调用 `getContentTxt()` 会丢失段落分行信息。
- 写入时调用 `setContent(html, false)` 立即回写至 `textarea`，并调用 `sync()` 再次同步表单。
- 填空题内容在提交时会被站点自动包裹 `<p>…</p>` 标签，此为超星平台原生逻辑。

## 异步保存与节流机制

考试整卷预览页的保存调用路径如下：

| 用户操作 | 触发的原生函数与流程 |
| --- | --- |
| 点击选项 | `saveSingleSelect` / `saveMultiSelect` $\rightarrow$ `submitForm(true, 单题容器, 回调)` |
| 点击主观题保存 | `a#save_{dataStr}` 的「保存」 $\rightarrow$ `saveQuestion(qid, dataStr)` |
| 点击交卷 | `finalSubmit()` $\rightarrow$ `submitForm(false)` |

其中 `dataStr` 为 `textarea` 的 ID 剥离前缀 `answer` 或 `answerEditor` 后的部分。

### submitOnce 节流机制

```js
function lockSubmit(lock) {
  if (lock) { window.submitOnce = true; $('body').css('pointer-events', 'none') }
  else { window.submitOnce = false; $('body').css('pointer-events', 'auto') }
}

function submitForm(tempSave, quietSubmit, callBack) {
  if (tempSave && window.submitOnce) { return }
  // 在 ajax complete 回调中调用 lockSubmit(false)
}
```

当前一个保存请求尚未返回时，超星前端会将 `window.submitOnce` 置为 `true`，此时后续触发的保存请求将被直接丢弃。实测若连续点击 5 道题，仅会发出 1 个 POST 保存请求，其余题目仅修改了页面选中样式而未真正持久化到服务端。

为此，脚本在每次操作前均需轮询等待 `window.submitOnce` 复位为 `false`，并在所有题目填写完毕后触发一次整卷保存。

### 答题卡状态同步

| 属性项 | 标识与取值 |
| --- | --- |
| 答题卡节点 | `#answerSheet{qid}` |
| 已作答样式标记 | class 包含 `active` |
| 状态更新函数 | `changeQuestionCardColor(qid)`（由保存成功回调触发） |

## 用户脚本沙箱与环境上下文

在 ScriptCat 与 Tampermonkey 等脚本管理器的沙箱环境中，直接访问 `window` 无法获取页面原生挂载的全局变量（如富文本编辑器实例 `window.UE`）。需通过 `unsafeWindow` 获取页面真实的上下文环境：

```js
const w = typeof unsafeWindow !== 'undefined' ? unsafeWindow : window
const ed = w.UE.getEditor(id, undefined, true)
```

DOM 触发操作（如 `element.click()`）跨沙箱原生有效，因此客观题选择不受沙箱隔离影响，仅依赖页面全局对象的主观题回写需要借助 `unsafeWindow`。
