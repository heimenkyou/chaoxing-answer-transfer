# 调试指南

本文介绍如何在本地搭建双账号独立浏览器环境，并通过 CDP 自动化调试客户端进行脚本注入与作答状态核验。

## 双账号独立调试环境搭建

本地联调时需为两个账号分别指定独立的用户数据目录（User Data Dir），避免登录 Cookie 与会话冲突：

```powershell
$root = "$env:LOCALAPPDATA\cx-helper"
New-Item -ItemType Directory -Force "$root\chrome","$root\edge" | Out-Null

Start-Process 'C:\Program Files\Google\Chrome\Application\chrome.exe' -ArgumentList `
  '--remote-debugging-port=9222', "--user-data-dir=$root\chrome", '--no-first-run', 'about:blank'

Start-Process 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe' -ArgumentList `
  '--remote-debugging-port=9223', "--user-data-dir=$root\edge", '--no-first-run', 'about:blank'
```

各账号的登录凭据保存在独立的 profile 目录中，浏览器重启后无需重新登录。

## CDP 调试客户端使用

项目在 `tools/cdp.mjs` 中提供了一个基于 Node.js 的轻量 Chrome DevTools Protocol 调试工具，可通过调试端口与浏览器页面直接交互：

```powershell
node tools/cdp.mjs list
node tools/cdp.mjs eval 9223 dowork "return location.href"
node tools/cdp.mjs evaljs probe.js 9223 dowork result.json
```

目标参数支持指定页面序号、URL 路径或页面标题片段；传入的 JavaScript 代码以函数体格式执行，通过 `return` 返回求值结果。

## 用户脚本注入与主窗口模拟

可通过 CDP 直接将用户脚本注入到目标作答页面中进行功能测试：

```powershell
node tools/cdp.mjs evaljs chaoxing-answer-transfer.user.js 9223 dowork
```

注入成功后，可在浏览器控制台执行 `window.__cxBridge()` 呼出操作面板（正常安装环境下由脚本管理器注册的菜单项触发）。

> **说明**：通过 CDP 注入的代码直接运行于页面的主执行环境（Main World），不受脚本管理器的沙箱隔离限制。若需模拟沙箱环境下的全局对象行为，可手动挂载：
> ```js
> window.unsafeWindow = { UE: window.UE }
> ```

## 服务端持久化状态校验

超星前端页面的「已作答」样式仅表示本地 DOM 发生了变更。若异步保存请求因接口节流被丢弃，刷新页面后作答可能出现回退。为验证填写是否真正保存成功，应直接请求当前页面以服务端实际返回的 HTML 为准：

```js
const html = await fetch(location.href, { credentials: 'include' }).then(r => r.text())
const doc = new DOMParser().parseFromString(html, 'text/html')
```

通过解析服务端返回的 DOM，比对 `.questionLi[data]` 容器内对应选项 `span[data].className` 是否包含选中类名。对于填空题，由于 UEditor 在同步时会将文本包裹在 `<p>…</p>` 标签中，比对前需先剥离 HTML 标签。

## 常见问题与兼容处理

| 故障/异常场景 | 具体表现 | 解决方案与适配机制 |
| --- | --- | --- |
| `submitOnce` 接口节流 | 连续快速点击多个选项时，仅首个保存请求生效 | 异步操作前轮询等待 `window.submitOnce` 复位为 false，完成后触发整卷保存 |
| 脚本管理器沙箱隔离 | 访问 `window.UE` 为 undefined，导致主观题未写入 | 通过 `unsafeWindow` 获取页面真实的上下文环境 |
| 选项顺序被打乱 | 选项字母（A/B/C/D）无法在账号间直接对应 | 忽略字母，基于选项实际文本进行对齐匹配 |
| `aria-checked` 属性残留 | 切换选项后，原选项上的属性值仍为 true | 改用 `check_answer` / `check_answer_dx` 类名判断选中状态 |
| 题目题号不同 | 题干文本比对受题号前缀干扰 | 优先基于题目容器的 `data` 属性（题目 ID）对齐 |
| 填空答案带空位编号 | 答案详情中带有的 `(1)`、`(2)` 等前缀被误填入输入框 | 解析阶段自动剥离空位编号正则 |
| 真实考试环境调试 | 测试回填会覆盖已有作答 | 测试前先读取并导出初始作答，测试后恢复原状并核验 |
